# دليل GitHub: الرفع، التنزيل، التحديث، والملاحظات الفنية

هذا الدليل لا يحتاج أي خبرة برمجية. كل الخطوات بالضغط على الأزرار.

---

## الجزء الأول: رفع المشروع (أنت، مرة واحدة)

### 1. إنشاء حساب وتثبيت GitHub Desktop
1. أنشئ حساباً مجانياً على github.com.
2. ثبّت برنامج **GitHub Desktop** من desktop.github.com وسجّل الدخول بنفس الحساب.

### 2. إنشاء المستودع
1. فك ضغط `UniHub-source.zip` في مجلد، مثلاً `Documents\unihub`.
2. في GitHub Desktop: **File ← Add local repository** واختر المجلد.
3. سيقول إنه ليس مستودعاً، اضغط **create a repository** ثم **Create repository**.
4. اضغط **Publish repository** في الأعلى.
   - الاسم: `unihub`
   - **أزل علامة** «Keep this code private» (يجب أن يكون عاماً حتى يعمل التحديث عند صديقك بدون مفاتيح).
5. اضغط **Publish repository**.

> المستودع العام يعني أن الكود مرئي للناس، لكن **لا توجد فيه أي بيانات شخصية**: كلمات المرور والمفاتيح وملفات الجامعة كلها تبقى على أجهزتكما فقط.

### 3. تفعيل Issues
في صفحة المستودع على الموقع: **Settings ← General ← Features** وتأكد أن **Issues** مفعّلة.

### 4. نشر الإصدار الأول
1. في صفحة المستودع اضغط **Releases ← Create a new release**.
2. في **Choose a tag** اكتب `v1.0.0` واختر **Create new tag**.
3. العنوان: `منظّم الجامعة v1.0.0`، وفي الوصف اكتب ما تريد.
4. اضغط **Publish release**.
5. انتظر 2–3 دقائق. GitHub يبني البرنامج تلقائياً (تبويب **Actions** يظهر التقدم)، ثم تظهر الملفات `UniHub.exe` و `UniHub-Windows.zip` في صفحة الإصدار.

## الجزء الثاني: التنزيل (أنت وصديقك)

1. افتح: `github.com/<اسم-حسابك>/unihub/releases/latest`
2. حمّل **UniHub.exe** وشغّله.
3. اضغط **تثبيت** في الشريط العلوي، ثم اربط حساب المودل.

> مهم: النسخة التي تنزل من GitHub هي التي تعرف مكان التحديثات تلقائياً. النسخة التي أرسلتها لك في المحادثة لا تعرف اسم مستودعك؛ إذا استخدمتها اكتب `اسم-حسابك/unihub` في **الإعدادات ← التحديثات**.

---

## الجزء الثالث: كيف يعمل التحديث التلقائي

- البرنامج يفحص GitHub بعد التشغيل بدقيقة، ثم كل 6 ساعات.
- عند وجود إصدار أحدث: ينزّله، يتحقق من سلامته (SHA-256)، **يحفظ نسخة احتياطية من بياناتك**، يستبدل نفسه، ويعيد التشغيل خلال ثوانٍ، ثم يعرض «ما الجديد».
- بياناتك في `%AppData%\UniHub` وملفات الجامعة في مجلدها، والتحديث لا يلمس أياً منهما.
- يمكن إيقاف التحديث التلقائي من الإعدادات، والتحديث يدوياً بزر «تحديث الآن».

## الجزء الرابع: الملاحظات الفنية (الحلقة بينك وبين صديقك وClaude)

### الإعداد (كل واحد منكما مرة واحدة)
1. صديقك ينشئ حساب GitHub مجاني.
2. في البرنامج: **الملاحظات الفنية ← اضغط هنا لإنشاء مفتاح**، ينزل للأسفل ويضغط **Generate token**، ثم ينسخ المفتاح ويلصقه في البرنامج.
3. المستودع يكون مكتوباً تلقائياً، اضغط **ربط**.

### الدورة الكاملة
1. **صديقك** يكتب ملاحظة (خطأ / اقتراح / تحسين / سؤال) ويضغط إرسال. بدون إنترنت تُحفظ وتُرسل لاحقاً.
2. **أنت** يصلك تنبيه ويندوز، وتظهر الملاحظة في البرنامج، ويمكنكما التحاور بالردود.
3. **أنت** تضغط «نسخ للإصلاح» وتلصق النص في محادثة مع Claude، أو تقول له: «اقرأ الملاحظات المفتوحة من مستودعي» إذا كان GitHub مربوطاً.
4. **Claude** يصلح الكود. إذا أعطيته صلاحية على المستودع يرفع التعديلات بنفسه وينشر إصداراً جديداً؛ وإلا يعطيك ملفات المشروع المحدّثة.
5. إذا أعطاك ملفات: انسخها فوق مجلد المشروع، وفي GitHub Desktop اكتب وصفاً قصيراً واضغط **Commit to main** ثم **Push origin**، ثم أنشئ إصداراً جديداً بالرقم التالي (`v1.0.1` مثلاً) كما في الخطوة 4 من الجزء الأول.
6. **عند كليكما** يتحدث البرنامج تلقائياً، وتضغط «تم الحل» على الملاحظة.

### قاعدة أرقام الإصدارات
- إصلاح صغير: `v1.0.0` ← `v1.0.1`
- ميزة جديدة: `v1.0.1` ← `v1.1.0`
- الرقم يجب أن يكون دائماً أكبر من السابق، وإلا لن يعتبره البرنامج تحديثاً.
